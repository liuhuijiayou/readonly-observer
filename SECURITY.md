# Security scope (0.3)

Observer is a single-operator, local read-only MCP gateway. The local OS user, installed Observer/Python/Git and the explicitly chosen transport/client are trusted. Project files, session logs, tool outputs and remote prompts are untrusted. A malicious process under the same OS identity or an already compromised machine is outside this application boundary. This is application-level scope enforcement, not a kernel sandbox or per-remote-user authorization service.

## Access and data handling

New CLI instances have no sources. Only local confirmation (or the local operator's explicit `--approve`) registers a project or exact JSONL file and metadata ID. MCP has 13 read-only tools, no lifecycle/approval/command execution endpoints, no ability to broaden roots, and no network calls. Remote paths and instructions in source content cannot register sources. Legacy explicit config entry points remain supported for their existing operator-selected scopes; no automatic import occurs.

Paths use pinned directory descriptors, component-by-component no-follow opens, regular-file and strict hardlink checks. Source versions are checked around reads and page continuation. Raw source logs and credentials are not exposed through workspace reading. Session projection only admits recognized public channels/fields, excluding reasoning, internal and unknown channels. Static wrapper extraction recognizes a narrow literal grammar and never evaluates strings.

Redaction precedes searching, clipping and pagination. Known assignments, token patterns, URLs and private-key blocks are covered; it is heuristic and cannot detect every secret. Permission to read a project still exposes all permitted public content, including ignored/untracked files. Do not approve a project whose permitted content you are not willing to share with the connected client. A configured remote transport's access is shared across its clients; no per-user OAuth or tenant isolation is implemented.

Git uses fixed argv in private sealed byte snapshots. Source config, hooks, filters, helpers, external diff/textconv, system/global config, optional index locking, lazy fetch and network protocols are disabled. Constrained SHA-1 repositories with ordinary local/remote/packed refs and paired pack/idx files are supported. Main-repository `.git/worktrees` management records and derived commit-graphs/bitmaps/MIDX are omitted; external gitdir/linked checkouts, alternates, shallow/promisor, submodule/symlink index modes and worktree skip/assume-unchanged flags fail closed. History omits the index/worktree; staged diff omits the worktree. Literal pathspecs also bound worktree copying, while the local object database is still copied within budget. Untracked files contribute names/metadata only, never invented content patches. Sanitized results need not match custom filter semantics. Fixed native Git queries are infrastructure reads, not execution of observed project commands. Snapshot copying may fail on concurrent changes; evidence is sequential, not an atomic live transaction.

## Runtime and credentials

Instance config/state/cache/logs are separate, private (0700/0600). stdio manager control and MCP endpoints are private Unix sockets, with bounded relay buffers, maximum four workers, locks and source snapshots. Stop operates through this instance's socket on its own children; no PID-file kill, process-name discovery, takeover or automatic stale-file deletion. Existing terminal services and their environments are not inspected. Source/transport changes activate only after an explicit stop/start; remove-and-stop is required for revocation of already running workers.

Optional official Tunnel adaptation is separate from the stdio reader and is not bundled. It creates no remote credentials or tunnel. macOS Keychain storage requires the operator's explicit local secure-TTY confirmation. The instance-specific service/account is shown without reading the value. Keys never enter config, CLI args or raw logs; only an explicit tunnel start retrieves that instance key into its owned client environment, while MCP workers use `env -i`. No autostart, browser automation or system security changes.

## Limits and evidence

Responses 32 KiB; MCP input frame 64 KiB; JSONL records 256 KiB; workspace source file 4 MiB; Git snapshot 100 MB (100,000,000 bytes) combined; scan 4 MiB/1 second/4,000 entries; session prefix verification 64 MiB; regex 15 ms; cursor TTL 600 seconds, 256 entries and 4 MiB state. Git additionally limits worktree bytes to 64 MiB, individual worktree files to 16 MiB, pack/object files to 100,000,000 bytes (still subject to the combined cap), small metadata files to 4 MiB, inventory to 50,000 entries and creation to 20 seconds. Each native query has a 5-second wall deadline, a 6-second CPU limit, a 4 MiB combined stdout/stderr limit and a 128 KiB argument limit. Core dumps/file writes are disabled in the Git child; allocation requests are capped at 128 MiB and Git pack caches are bounded. This is not a hard total-RSS limit on macOS. Budget accounting conservatively includes source bytes read, generated config and enumerated names. Any refusal is incomplete; `clean` cannot be inferred. Full content is available only within these bounds. Expired/restarted/evicted cursors must be reacquired; bound operations, sources and versions cannot be mixed. Unknown structures have no raw fallback.

Historical completion and exit zero do not prove task correctness or current activity. `evidence_link` reports associations and trace-reported hashes, not causation. Local startup/probe does not establish remote transport connectivity, ChatGPT metadata or end-to-end success. Platform verification is explicitly limited in the release evidence.

## Vulnerability reporting and release status

Use [GitHub private vulnerability reporting](https://github.com/liuhuijiayou/readonly-observer/security/advisories/new) to contact the repository maintainer, `liuhuijiayou`. A GitHub account is required. Include a minimal synthetic reproduction, the affected Observer version and the expected security boundary. Do not publish sensitive source, logs, credentials or exploit data in a public issue. No personal email address, bug bounty or response SLA is offered.
